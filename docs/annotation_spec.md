> 版本：0.1（2026-11-20）
> 对应数据：`backend/data/dataset_full.csv`（168 条）
> 依据：V3 6.6「标注规范与样本集」、五部门「招转培 / 培训贷」风险提示
> 说明：本规范描述的是**当前数据集实际采用的标注口径**，不是事后补写的理想流程。
> 尚未完成双人标注与 Kappa 计算，相关计划在第七节如实列出。

## 一、标注单位与字段

一条样本 = 一条招聘 JD。CSV 字段：

| 字段 | 说明 |
|---|---|
| `id` | `P-xxx` 正样本 / `NP-xxx` 成对反例 / `N-xxx` 公开招聘负样本 |
| `label` | `1` 招转培风险；`0` 正常 / 未发现；`-1` 信息不足 |
| `category` | 当前正样本统一为 `招转培风险` |
| `jd_text` | JD 原文，保持原样，不做清洗改写 |
| `spans` | JSON 数组：`[{"phrase": "...", "start": 0, "end": 4}]` |
| `phrase_ids` | 命中的词表条目，分号分隔 |
| `source` | 来源类型（官方话术构造 / 公开招聘 / 成对反例） |
| `platform` | 平台名称 |
| `source_url` | 可回溯的原始链接（真实岗位） |
| `fetched_at` | 采集或构造时间 |

## 二、标签定义

### 2.1 二分类

| 标签 | 判定 |
|---|---|
| `1` | JD 存在明确的招转培 / 培训贷风险：以招聘为名，实际引导付费培训、贷款或与录用绑定的收费环节 |
| `0` | 正常招聘，或仅出现可解释为正规用工的培训、薪资、经验要求 |
| `-1` | 原文过短、关键信息缺失、无法判断；不硬猜 |

### 2.2 多标签话术类别

当前词表 `app/data/phrases.json` 的 7 类：

| 类别 | 典型话术 |
|---|---|
| 零门槛类 | 零门槛、无需任何基础、不限专业、零基础可投 |
| 高薪异常类 | 月入过万、月入轻松过万、上不封顶、薪资无上限 |
| 面试即入类 | 面试即入职、当天入职、当天上岗 |
| 能力打压类 | 岗位有技能门槛、能力不足、岗前培训、内部实训 |
| 培训诱导类 | 包就业、包上岗、安排就业、培训后快速上岗 |
| 收费诱导类 | 费用可分期、实训费、押金、保证金、费用自理 |
| 贷款诱导类 | 培训贷、可协助办理分期、指定平台贷款、先学后付 |

`主体分离`、`沟通异常` 不靠词表单独判定，由 F-03 一致性校验与 F-06 主体核验处理。

## 三、Span 标注规则

1. **字符级偏移**：`start` 包含、`end` 不包含；`jd_text[start:end]` 必须与 `phrase` 完全一致。
2. **标最有信息量的完整短语**：例如标「零基础可投」，不标「零基础」加「可投」两段。
3. **不跨标点**：span 内不包含逗号、句号、分号、换行。
4. **一条 JD 可标多个 span**：不要只标第一个命中的词。
5. **正负成对时保持最小差异**：只改与风险绑定关系相关的部分，便于模型学习上下文而不是学岗位名。
6. **标签为 0 的样本默认不标 span**；如确有必要记录“看似风险但实际正常”的短语，在判定依据中说明，不计入正样本 span。

校验命令：

```bash
cd backend
python scripts/label_tool.py check
```

当前结果：168 条，span 偏移问题 0 个，无 span 样本 0 条。

## 四、边界裁决规则（必须写死）

### 4.1 培训话术

**判风险**：培训与收费、贷款、包就业、录用结果绑定。

- 正例 `P-025`：「公司提供岗前技能培训（费用自理，可分期），培训合格直接安排就业」
- 正例 `P-037`：「入职需先参加内部实训（实训费3980，可协助办理分期），实训结束保证就业」

**不判风险**：免费、入职后、本公司内部实施、不与录用结果挂钩。

- 负例 `NP-001`：「入职后有带薪岗前培训，由本公司内部实施，不收取任何费用」
- 负例 `NP-009`：「公司提供免费入职培训，培训期间正常发放工资」
- 负例 `NP-017`：「岗前培训免费，为期一周，不与录用结果挂钩」
- 负例 `N-039`：「公司提供岗前培训」

注意：不能只匹配「培训」两个字；要读同一句里的费用、分期、录用等绑定关系。

### 4.2 薪资区间

单独的「8-15K」不是风险话术。只有与零门槛话术同时出现、构成「零经验 + 高薪」时才作为
高薪诱饵证据。当前规则引擎采用组合信号：零门槛命中 + 薪资下限 ≥ 8K，才追加扣分。

### 4.3 押金 / 保证金

- 入职前向求职者收取的押金、保证金、服装费、材料费 → 收费诱导。
- 岗位职责中提到的客人押金、房费押金（如酒店前台 `N-087`）→ 不是风险，不能标注。
- 规则引擎目前按关键词命中「押金」会给低分提示，这是已知误报，不能据此判高危。

### 4.4 经验与学历要求

「1年以上经验」「大专学历」属于正常要求，不标风险。只有与「零基础也可」「不限学历」
同时出现、且后续引导培训/收费时，才把零门槛部分标为风险。

### 4.5 信息不足

以下情况标 `-1`，并在判定依据中写明缺什么：

- 只有一句「高薪诚聘」，没有岗位、公司、流程信息；
- 截图 OCR 残缺，主体名或收费环节被截断；
- 无法判断培训是否收费、是否与录用绑定；
- 同一 JD 出现互相矛盾的版本。

## 六、标注流程

1. **预标注**：用 `phrases.json` 词表跑一遍，生成候选 span，人工逐条确认。
2. **人工复核**：逐条读原文，确认标签、类别、span 边界。
3. **一致性检查**：`label_tool.py check` 校验偏移；人工抽查 20%。
4. **争议裁决**：培训、押金、薪资三类边界必须由第二人复核。
5. **版本冻结**：数据集冻结后打 tag，实验只使用冻结版本。

## 七、一致性与复核（当前进度）

- 目前为**单人标注**，尚未计算 Cohen's Kappa。
- 计划：间隔两周重标 50 条；另请一位同学独立标 50 条；计算简单一致率与 Kappa。
- 目标：Kappa ≥ 0.70；低于该值时先修订边界规则，再扩充数据。
- 在论文中如实写「已完成单人标注与偏移校验，双人一致性检验待完成」，不要编造 Kappa。

## 八、常见坑

1. 正样本全是一眼假的「零基础月入过万」→ 模型退化成词表；至少掺 30% 隐晦变体。
2. 负样本全是大厂干净 JD → 模型学到公司名而不是话术；负样本要覆盖真实中小岗位。
3. 一个人标、前后标准漂移 → 定期回头重标，记录修订。
4. 只标标签不标 span → 原文高亮与解释支持率实验全部失效。
5. 把「培训」「押金」「薪资区间」单独当风险 → 大量误报；必须看上下文绑定关系。
6. 为凑数量爬取已下架或无法确认的岗位 → 没有标准答案，反而污染数据。
